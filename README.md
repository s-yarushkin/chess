# Шахматная академия / Chess Academy

**Статус: технический MVP, не публичный релиз.** Серверный тренажёр с Telegram Mini App, проверкой ходов, хранением прогресса, баллами и добровольным рейтингом. Первый этап рассчитан на локальную проверку и пилот, следующий — на отдельный production с PostgreSQL и полноценной базой задач.

## Что работает сейчас

- Telegram Mini App: проверка `initData` через HMAC-SHA256 на сервере, привязка к Telegram ID, первый вход с выбором отображаемого имени/ника.
- Локальный тестовый вход только с `DEV_MODE=1` и только с loopback-адреса.
- Игровая доска с обозначением сторон **Б / Ч**, подсветкой ходов, подсказками, звуком и анимацией мата.
- Мат в 1, 2 и 3 хода; защитные ничейные задачи только после экспертной проверки. Начисление очков на сервере, только за первое прохождение позиции.
- Прогрессивный режим: по мере тренировок открывается смесь более сложных категорий, выбираются случайные нерешённые позиции рядом с уровнем игрока. Позиции, показанные недавно, по возможности не повторяются.
- Персональная статистика и общий рейтинг **только при добровольном согласии**. Настоящее имя и фамилия не требуются.
- Импорт реальных задач из открытой базы Lichess (CC0). Экспорт Lichess содержит миллионы задач; официальный источник: https://database.lichess.org/#puzzles
- Автотесты API и шахматных сценариев (`npm test`).

## Честный статус контента

В репозитории **не лежат** тысячи готовых задач. Присутствуют 80 проверенных старых демопозиций (30 матов в 1 ход и 50 в 2 хода) и одна пробная строка CSV из официального Lichess для тестирования импортёра. Бывшие 20 «съешь последнюю пешку» в банк не перенесены. До публичного старта необходимо загрузить реальную базу и провести методическую ревизию ничейных задач.

Скрипт `npm run audit:catalog` требует минимум **300 матов в 1, 500 матов в 2, 300 матов в 3 и 200 качественных защитных задач на ничью**. Пока это условие не выполнено, он возвращает ошибку.

## Локальный запуск

Требуется Node.js **22.5+** (рекомендуем Node 22 LTS). Внешние npm-библиотеки для первого MVP не требуются. `node:sqlite` в Node 22 помечен experimental; см. ограничения ниже.

```bash
# Из корня репозитория
npm test
npm run import:demo     # только демонстрационные позиции, не для production
npm run dev             # http://127.0.0.1:8094
```

Откройте `http://127.0.0.1:8094` на том же компьютере. Появится тестовый вход по имени. При боевом запуске `DEV_MODE=0`; вход доступен **только через Telegram**.

## Импорт Lichess

1. Скачайте файл `lichess_db_puzzle.csv.zst` с https://database.lichess.org/#puzzles.
2. В системе с установленным `zstd` выполните:

```bash
# Стандартно: 750 проверенных задач каждой матовой категории
zstd -dc lichess_db_puzzle.csv.zst | DB_PATH=./storage/chess.sqlite node scripts/import-lichess.js -
# При необходимости увеличить размер каталога
zstd -dc lichess_db_puzzle.csv.zst | LIMIT_PER_CATEGORY=1500 DB_PATH=./storage/chess.sqlite node scripts/import-lichess.js -
npm run audit:catalog
```

Импортёр сохраняет позицию **после первого хода** (согласно формату Lichess), извлекает решение, проверяет каждую законную полуходовую последовательность и финальный мат. Отбор по популярности, числу сыгранных попыток и неопределённости рейтинга. `mateIn1`, `mateIn2`, `mateIn3` становятся `mate1`, `mate2`, `mate3`.

**Важно:** импортёр проверяет сохранённую линию, но не исчерпывающую доказанность мата против каждой возможной защиты. Публикация в Lichess уже включает шахматный анализ; для спорных комбинаций и школьного каталога нужен дополнительный аудит движком. Задачи «equality» нельзя автоматически переименовывать в «форсированную ничью».

## Telegram Mini App

1. Создайте **отдельного** бота через @BotFather; не используйте токены существующих ботов других проектов.
2. Укажите отдельный HTTPS-адрес Mini App, на котором этот сервер опубликован через обратный прокси (Caddy/Nginx).
3. В переменные окружения добавьте `TG_BOT_TOKEN`, `TG_WEBHOOK_SECRET`, `WEBAPP_URL`, `DB_PATH`. Не сохраняйте реальные токены в Git.
4. Запустите `node src/server.js` за HTTPS-прокси. Затем однократно `npm run bot:setup`. Эта команда настраивает Telegram webhook и пункт меню «Играть в шахматы».
5. При первом входе Telegram проверяется на сервере, игрок вводит имя или никнейм, включение общего рейтинга — по желанию.

Пример переменных — `.env.example`. Для локальной загрузки файла окружения:

```bash
node --env-file=.env src/server.js
```

## API

| Метод | URL | Назначение |
|---|---|---|
| `GET` | `/healthz` | Проверка сервера |
| `POST` | `/api/auth/telegram` | Безопасная авторизация Telegram через `initData` |
| `POST` | `/api/auth/dev` | Только localhost + `DEV_MODE=1` |
| `GET`, `PATCH` | `/api/me` | Профиль, ник, участие в рейтинге |
| `GET` | `/api/catalog` | Доступные категории и очки |
| `POST` | `/api/attempts` | Выбор случайной задачи |
| `GET` | `/api/attempts/:id` | Продолжить текущую позицию |
| `POST` | `/api/attempts/:id/move` | Проверка хода UCI и ход соперника |
| `POST` | `/api/attempts/:id/hint` | Подсказка с уменьшением баллов |
| `GET` | `/api/leaderboard` | Никнеймы игроков с opt-in |
| `POST` | `/telegram/webhook` | Команды Telegram-бота |

`Bearer`-токен авторизует запросы; в базе хранится только его SHA-256. Сервер не отправляет эталонную линию решения до прохождения задачи.

Исходники публикуются в отдельном репозитории: https://github.com/s-yarushkin/chess (ветка `main`).

Если доступ должен быть ограничен, смените видимость в GitHub → Settings → General → Danger Zone → Change repository visibility → Private. Приложение при этом по-прежнему не развёрнуто и не доступно пользователям.

## Ограничения перед публичным запуском

- Пилот использует SQLite `node:sqlite` под одним процессом. Для полноценного многопользовательского продукта требуется **PostgreSQL 16**, миграции, журнал событий, резервные копии, нагрузочное тестирование.
- Нет полноценного экспертного банка ничьих; **не** добавлять бессмысленные позиции вместо настоящих защитных упражнений.
- В матах 2/3 проверяется эталонная линия Lichess; для всех возможных ответов соперника и альтернативных правильных решений позже интегрировать Stockfish или готовое доказательство.
- Видеоуровень анимации предварительный; визуальное тестирование на реальных Telegram-клиентах ещё требуется.
- Рейтинг и античит базовые. Для соревнований нужны сезоны, аудит попыток и защита от массового перебора API.
