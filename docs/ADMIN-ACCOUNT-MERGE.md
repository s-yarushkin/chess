# Разовое объединение двух Telegram-аккаунтов

**Только** для @SergeyYarushkin → @N_Yarushkina.

## Цель

В обоих Telegram-аккаунтах открывается **один шахматный профиль**: основной профиль @N_Yarushkina. Решения и очки объединяются без повторного зачёта одинаковых позиций.

## Процедура

1. Через @SergeyYarushkin открыть @Chess_by_Alex_bot → «Играть в шахматы» → «Мой профиль». В закрытом служебном разделе нажать «Создать разовый код».
2. Передать код напрямую владельцу @N_Yarushkina. Код действителен 15 минут.
3. Через @N_Yarushkina открыть приложение и профиль. Ввести код и нажать «Проверить перед объединением». Проверить количество решённых задач каждого профиля и прогноз объединения.
4. На @N_Yarushkina нажать «Подтвердить объединение» и подтвердить действие.
5. Закрыть игру и открыть снова из обоих Telegram-аккаунтов. Баллы и никнейм должны совпадать.

**Нельзя** завершить объединение по одному @username или коду: каждый шаг требует вход с подписанными Telegram Mini App данными соответствующего аккаунта. Служебный интерфейс скрыт от посторонних. Endpoint также проверяет подпись и точную пару Telegram-имён на сервере.

## Что изменится в Neon

- Таблицы: linked_telegram_identities, admin_merge_requests, admin_account_merges (создаются автоматически).
- Основной пользователь — профиль @N_Yarushkina; его настройки приватности и никнейм сохраняются.
- Completions из исходного профиля копируются с `ON CONFLICT ... GREATEST(points) / LEAST(solved_at)`. Очки и число решений пересчитываются из уникальных задач.
- Attempt history копируется; незавершённые задачи закрываются как пропущенные.
- Активные сессии исходного профиля переключаются на основной.
- Исходные записи пользователя и его решений **не удаляются**; сохраняются для отката и аудита.
- Если у исходного аккаунта есть приглашения, друзья, заявки или лиги, автоматическое объединение останавливается. Никакие такие связи не удаляются.
- После завершения SQL-аудит блокирует повторное использование операции.

## Проверка и ограничение

- `node --test tests/admin-account-merge.test.js` на временной Postgres в GitHub Actions: HMAC обеих учёток, согласие, уникальные задачи, копирование попыток, блокировка друзей, одноразовость, повторный вход.
- В публичной игре не добавляется массовая функция объединения аккаунтов.
- **Фактическое объединение в production не происходит до подтверждения из обоих Telegram-аккаунтов.**
- После выполнения разовой операции служебную форму и маршруты рекомендуется удалить отдельным релизом; таблицу аудита оставить.
