# Chess Academy — Vercel + Neon (открытый Telegram-вход)

## Публичный вход
- Любой пользователь с действующим Telegram-аккаунтом может открыть Mini App, выбрать отображаемое имя и решать шахматные задачи.
- Сервер проверяет подпись `Telegram.WebApp.initData` и время выдачи (`auth_date`). Не принимаем просто имя, Telegram ID или неподписанные данные в качестве авторизации.
- Переменная `PILOT_TELEGRAM_IDS` больше не используется; ранее созданную можно удалить из настроек Vercel.
- В UI показано приветствие: тренажёр запустили 8-летний Алексей и его папа Сергей.
- Нет публичного списка профилей, личной переписки или открытого рейтинга. Функции друзей пока скрыты; перед включением необходимо проверить безопасные настройки приватности.
- Не требуем фамилию, возраст, номер телефона или адрес.

## Запуск
1. Vercel-проект `chess-academy` связан с `s-yarushkin/chess` (ветка `main`).
2. База Neon PostgreSQL связана с проектом; переменная `DATABASE_URL` должна быть доступна в **Production**.
3. `TG_BOT_TOKEN` хранится в **Environment Variables → Production**; никогда не помещайте его в репозиторий, чат или публичные логи.
4. Публичная точка проверки `GET /healthz`: ожидаются `status: ok`, `database: connected`, каталог из 900/1100/1000 задач.
5. В BotFather `Menu Button` и `Configure Mini App` должны ссылаться на HTTPS production URL.
6. После нового production-deploy откройте игру через бот, выберите имя, решите задачу, перезапустите Mini App и проверьте сохранение баллов.
7. `TG_WEBHOOK_SECRET` / `WEBAPP_URL` нужны только для команд бота через webhook; простая кнопка Mini App работает без webhook.

## Архитектура
- `api/index.js` — Vercel Function, `public/` — веб-интерфейс.
- Neon хранит пользователей, сессии, попытки и результаты. Каталог из 3 000 позиций упакован с функцией.
- SQL использует параметризованные запросы; повторные решения одной позиции не дают баллы повторно.
- Обычный запуск сайта вне Telegram не даёт доступ к игре: для авторизации нужен подписанный `initData`.
- Node/SQLite backend оставлен для локальных тестов и не используется в production Vercel.

## Проверки
- `npm test` — включая публичную Telegram-авторизацию, неподдельность подписи и состояние экрана первого входа.
- Реальный smoke-test в Telegram: вход двух разных аккаунтов, независимые баллы, обновление профиля, повторный вход.
- Если `/healthz` возвращает 503, проверьте `DATABASE_URL` и логи Vercel Functions.
- Если Telegram Mini App открывает страницу Vercel Authentication, настройте Deployment Protection после проверки собственного механизма авторизации.
