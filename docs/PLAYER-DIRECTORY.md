# Каталог игроков, дружба и приглашения в лиги

## Для ученика

1. При регистрации выбери **уникальный никнейм** (2–24 символа, буквы/цифры/подчёркивание/дефис, без фамилии, школы и контактов). Никнейм регистронезависим: Лёша и лёша считаются одинаковыми.
2. В профиле включи «Делиться прогрессом с подтверждёнными друзьями» и, если хочешь, **отдельно** «Показывать мой никнейм в списке игроков».
3. В «Друзьях» виден список никнеймов тех, кто согласился показываться; поиск и 30 игроков на страницу. Кнопка «Добавить в друзья» создаёт запрос. Получатель выбирает «Принять» или «Отклонить». Без двух согласий никакого обмена результатами нет.
4. В «Лигах» создатель открывает свою лигу, выбирает несколько игроков из каталога и нажимает «Пригласить выбранных». Они увидят приглашение в разделе «Меня пригласили» и смогут принять или отказаться. Пока они не приняли, их в лиге нет.
5. При входе в приложение кнопки «Друзья» и «Лиги» показывают количество ожидающих запросов. Telegram-уведомления о приглашениях **не отправляются**: только внутри Mini App, без спама.

## Для безопасности

- Каталог по умолчанию **выключен**, пока пользователь явно не разрешит показывать свой никнейм. Список не содержит Telegram usernames, номеров, ФИО, контактов, школы, времени активности, баллов или общего рейтинга.
- Прогресс друзей виден после взаимного подтверждения, прогресс лиги — после принятия приглашения и вступления. Отключение sharing немедленно убирает игрока из каталога и скрывает результаты от других.
- До 20 друзей; максимум 6 новых запросов в друзья в сутки, повтор отклонённого запроса — не раньше недели. Создатель приглашает максимум 10 игроков в сутки, повтор отклонённого приглашения — через неделю. Лиги ограничены 20 игроками.
- Старые коды дружбы и лиг спрятаны в «Пригласить по старому коду», но остаются действительными. Существующие связи не удаляются.
- При добавлении уникального никнейма существующие пользователи и их достижения **не удаляются**. Унаследованные одинаковые имена могут не иметь nickname_key и не попадают в каталог; при сохранении профиля игроку предложат выбрать уникальный никнейм.

## Техническое устройство

- `users.nickname_key` — уникальный регистронезависимый ключ, nullable для legacy-профилей; `users.directory_visible` — флаг согласия, false по умолчанию.
- `league_direct_invitations` — запросы вступления в лиги с подтверждением получателя; старая таблица `league_requests` для заявок по коду остаётся.
- API: GET `/api/players`, POST `/api/friends/requests/direct`, GET `/api/leagues/invitations`, POST `/api/leagues/:id/invitations`, POST `/api/leagues/invitations/:id/{accept,decline}` и GET `/api/social/pending`.
- Тесты PostgreSQL подтверждают уникальность, приватность, отправку/подтверждение дружбы, приглашение/принятие/отказ и отключение публикации.
